# zeda 第二阶段任务开发 — 组合逻辑电路管理

## 背景

zeda 是数字逻辑电路学习/仿真平台：从逻辑门起步，逐步扩展到组合逻辑、时序逻辑、封装元器件，最终可在线上实现可执行指令的处理器。

第一阶段已完成纯前端骨架与「逻辑门管理」闭环（列表 / 详情公式设计 / 单门仿真），详见 [task01.md](./task01.md)。

第二阶段目标：在阶段一之上完成「组合逻辑电路管理」闭环——列表管理、画布连线设计、网表级组合仿真，并提供常用组合电路与代表性 74LS 黑盒作为内置库。

## 原始要求（验收基准）

继承阶段一不变项：

1. 技术栈：`pnpm` + Vite + React + TypeScript + Tailwind CSS + shadcn/ui，纯前端
2. 存储：浏览器 IndexedDB（Dexie）
3. 性能热点后续可用 Rust + WASM（本阶段不做）
4. AppShell：顶栏、底栏、左侧栏可折叠；适配不同屏幕
5. URL base：`/zeda`
6. 可切换主题（亮/暗）与语言（简体中文 / 英文 / 繁体中文）
7. 逻辑门符号继续用美国 ANSI 标准（画布上门实例复用阶段一 `GateSymbol`）

本阶段新增：

8. 组合逻辑电路的管理与画布连线设计（多门/模块互连，非单门）
9. 内置常用组合电路：加法器、编码器、译码器
10. 自定义组合电路；内置少量代表性 74LS 系列黑盒模块供引用与学习
11. 纯组合电平仿真（无时钟、无波形）

### 数据模型要点

```ts
// 示意；实现时可微调字段名，但语义需对齐
type CircuitPin = { id: string; name: string }

type CircuitNode =
  | {
      id: string
      kind: 'gate'
      /** 引用阶段一 LogicGate：优先 builtinKey，其次 gateId */
      ref: { builtinKey?: string; gateId?: string }
      position: { x: number; y: number }
    }
  | {
      id: string
      kind: 'module'
      /** 内置黑盒，如 half_adder / 74ls138 */
      moduleKey: string
      position: { x: number; y: number }
    }

type CircuitWire = {
  id: string
  /** 源/宿：电路对外口或节点引脚 */
  from: { nodeId: 'io' | string; pinId: string }
  to: { nodeId: 'io' | string; pinId: string }
}

type ComboCircuit = {
  id: string
  name: string
  description?: string
  kind: 'builtin' | 'custom'
  builtinKey?: string
  inputs: CircuitPin[]
  outputs: CircuitPin[]
  nodes: CircuitNode[]
  wires: CircuitWire[]
  createdAt: number
  updatedAt: number
}
```

约束：

- 叶子只能是阶段一门实例，或本阶段内置/种子黑盒模块
- **自定义电路不可再作为节点嵌套进另一自定义电路**（层级封装归后续阶段）
- 门引用解析失败（缺门、坏 id）须明确报错，不静默当成恒 0

## 内置电路目录（冻结清单）

种子必须覆盖下列条目；名称可本地化，行为与 IO 语义固定。

实现约定（已落地）：内置加法器 / 编解码 / 七段，以及 74LS 代表件，均以**门级网表**种子写入（`internals.ts`）；74LS 种子以 **custom** 落库（可编辑/删除），其余为 **builtin** 只读。列表与下钻视图共用同一套门级拓扑。

### 加法器

| builtinKey（建议） | 名称 | IO 要点 |
|--------------------|------|---------|
| `half_adder` | 半加器 | 入 A,B；出 Sum, Cout |
| `full_adder` | 全加器 | 入 A,B,Cin；出 Sum, Cout |

### 编码器

| builtinKey（建议） | 名称 | IO 要点 |
|--------------------|------|---------|
| `encoder_4_2` | 4→2 二进制编码器 | 入 I0–I3（互斥假设写清）；出 Y1,Y0；可选有效位 |
| `priority_encoder_8_3` | 8→3 优先编码器 | 入 I0–I7；出 Y2–Y0 + 有效/组信号（与常见教材一致即可，文档/UI 标明） |

### 译码器

| builtinKey（建议） | 名称 | IO 要点 |
|--------------------|------|---------|
| `decoder_2_4` | 2→4 二进制译码器 | 入 A1,A0；出 Y0–Y3 |
| `decoder_3_8` | 3→8 二进制译码器 | 入 A2–A0；出 Y0–Y7 |
| `seven_seg_decoder` | 七段数码管译码器 | 入 D3–D0（十六进制/BCD 约定写清）；出 a–g；**共阴**驱动假设（高电平点亮） |

### 74LS 代表黑盒（非整系列）

仅作集成块引脚与行为演示，不实现完整 74LS 家族：

| builtinKey（建议） | 器件 | IO / 行为要点 |
|--------------------|------|----------------|
| `74ls138` | 3→8 译码器 | A/B/C + G1/G2A/G2B 使能；Y0–Y7 低有效（按数据手册约定，UI 标明） |
| `74ls148` | 8→3 优先编码器 | I0–I7 等；编码输出与使能/GS 类信号（简化但可仿真） |
| `74ls283` | 4 位超前进位加法器 | A3–A0, B3–B0, Cin；S3–S0, Cout |

自定义电路：用户可在画布上用阶段一门 + 上述黑盒模块搭接任意组合逻辑（仍不可嵌套其他自定义电路）。

## 扩展优化（本阶段闭环后的增强项）

> 下列项**不纳入**第二阶段原始验收必须；在组合电路主闭环已可用的前提下继续迭代。

### 布线优化

目标：连线可读、可点选、少交叉，布局与走线解耦。

- [ ] **自动布局**：按拓扑分层（输入 → 门级 → 输出）排布节点，保证上下/左右足够间距，避免门卡片互相遮挡
- [ ] **正交/折线布线**：边采用正交路由（或等价折线），减少斜穿大跨度贝塞尔遮挡
- [ ] **交叉与拥堵处理**：对重叠边做局部偏移 / 跳线示意；扇出多的网优先主干再分支
- [ ] **IO 锚定**：输入固定左侧、输出固定右侧，始终在器件包围盒之外，不被节点盖住
- [ ] **选中高亮**：选中边时高亮该线及两端连接点；选中节点时高亮其全部关联连线；高亮色与仿真电平色（琥珀/绿）区分
- [ ] **一键整理**：工具栏「整理布线」对当前电路重新布局 + 重布线（可 undo）

### 根据表达式生成电路

目标：用户输入布尔表达式（或多输出公式），自动生成可仿真、可再编辑的门级网表。

- [ ] **输入**：复用阶段一公式语法（`AND` / `OR` / `NOT` / `XOR` / `XNOR`、括号、变量名）；支持多输出（每输出一条公式，或 `Y = …` 多行）
- [ ] **综合**：表达式 → AST → 门级网表（优先二输入门；必要时插入缓冲/非门）；非法式明确报错
- [ ] **布局落地**：生成的节点自动落位并走一版默认布线（衔接「布线优化」）
- [ ] **对外 IO**：从公式中的变量自动推断输入脚；输出名可编辑
- [ ] **入口**：详情页「由表达式生成」对话框；可选「替换当前画布」或「生成新自定义电路」
- [ ] **往返（可选增强）**：由现有网表导出多输出公式，与生成互为对照（大电路可懒生成）
- [ ] **约束**：生成结果仅为阶段一门实例 + 连线；不自动引入 74LS 黑盒；仍不可嵌套自定义电路

### 其它近期待增强

- [ ] 由网表导出等效多输出公式 / 真值表页（大 IO 数需懒分页）
